# Investor view page and monthly columns – design

Date: 2026-11-23 · Status: implemented

## Intent

The user asked: "add video action in inverstors, to show all inventors, deposits, withdraw, activity logs, just everything about the investors, and also in investors table, remove the email column, filter the table by the current month, add column current's month investment and return, also add Miscellaneous column", with a sheet as the example: per customer "September 1st €", "Return on investment Sept.", "October 1st €", … and "Miscellaneous" entries such as `-410 (15.8.) -415 (06.09.) +1074 (26.09.)`.

- "video" is read as **view**: a page with everything about one investor.
- The table gets the chosen month's investment on the 1st, return and miscellaneous movements, with a month filter that defaults to the current month.

## Decisions

- **Routes:** the view page is `/admin/investors/<id>`, the former detail page (name, email, password, deactivate / activate) moves to `/admin/investors/<id>/edit`. Existing links (creation redirect, registration notification) now land on the view page, which is where the admin wants to look first.
- **Actions column:** **Ansehen** (primary), **Bearbeiten**, **Deaktivieren / Aktivieren** as square icon buttons without text (the user's follow-up request), with a tooltip naming the action and aria-labels naming action and investor. The last sign-in column was dropped at the same time (still on the view and edit pages).
- **Figures follow the existing booking rules** (`src/lib/statements.ts`, pure and unit-tested; data from `src/server/queries/statements.ts`):
  - **Anlage am 1.:** the sum of all ledger entries with a value date before the 1st, plus every return of earlier months. A month's return counts from the 1st of the next month, so it belongs to the next month's opening, as in the sheet (831.585 + 107.479 = 939.064).
  - **Rendite:** the booked return for the month; "–" until it is booked.
  - **Sonstiges:** the month's deposits and withdrawals by value date (deposits by receipt date, withdrawals by request day), newest first, **net of fees** (deposit credit after fee, withdrawal payout plus fee), so that opening + return + booked movements = the next opening. Open requests are shown marked "offen" and don't count until approved; rejected ones are left out.
  - Ledger entries are grouped by value date in SQL; the group-by uses column positions because the time-zone conversion contains a bound parameter.
- **Month filter:** a select that submits on change, in its own GET form with the search and status as hidden fields; search, status filter and paging carry the month. Options run from the current month back to the first deposit (at most 24). The current month is not written to the URL.
- **No email column:** the search still matches emails; the view page shows the email under the name.
- **View page sections:** key figures (balance, available with reserved payouts, in the minimum term with pending deposits, total returns); monthly statement from the first deposit to the current month; deposits and withdrawals (newest 50 each, total shown when there are more), full width so the amounts aren't cut off; the paginated ledger; the investor's own activity log.
- **Activity log = the investor's own activity** (clarified by the user: "activity log i mean is specific user's activity log"): only entries the investor is the actor of (registration, sign-ins and sign-outs including failed and refused attempts, deposits booked, withdrawals requested, password changes). Admin decisions and pool-wide entries such as "returns booked" (whose details are the pool total) are left out; they show in the request tables and the pool-wide log. `listAuditLogs` takes an optional `actorUserId`. The log pages through everything (20 per page) with its own query parameter (`activity`), so it and the ledger (`page`) can page independently; both pagers keep the other's position and jump back to their section. The user column is hidden, since every entry is the investor's.
- **Follow-up (same day): "fix the padding, download CSV (month range) and also download CSV for each specific investors, also update Miscellaneous column, trim it but if click open popup to display all".**
  - **Select padding:** the browser's arrow sat against the right edge and the select was shorter than the search box. `Select` (`src/components/ui/select.tsx`) hides the native arrow and draws a chevron inset like the left padding, at the height of the text inputs; used by the month filter, the CSV popups and the returns page.
  - **Sonstiges trimmed with a popup:** the cell shows the two newest movements and "+N"; the whole cell is a button opening `Popup` (`src/components/ui/popup.tsx`, a native `<dialog>` above the scrolling table) with every movement, its reference and status, the booked total and the open amount. The view page's statement uses the same cell. `StatementMovement` now carries reference and status.
  - **CSV, all investors:** "CSV" above the list opens a popup with Von / Bis (default: shown month and the two before); the wide layout of the client's sheet, three columns per month, for every investor of the current filter (an unpaginated query sharing the list's filter). Route `/api/admin/investors/statements`.
  - **CSV, one investor:** a download icon per row (all months; a plain `<a download>`, because a `Link` would prefetch the route and log exports) and "CSV" on the view page with a month range; one row per month with booked deposit and withdrawal totals. Route `/api/admin/investors/[id]/statement`; file named by investor ID (ASCII).
  - **CSV rules** (`src/lib/statement-csv.ts`, unit-tested): months oldest first; plain numbers without "+" (so spreadsheets read them as numbers); Sonstiges starts with the date (a leading sign would be neutralised as a formula); range parsing defaults to the first deposit and the current month, orders swapped months, refuses malformed or future months and explicit ranges over 60 months. Exports are logged as `report.exported` (`investorStatements` / `investorStatement`, with range and investor). Both routes share the sign-in and admin check with the reports route (`src/server/csv-download.ts`).
- **Not built:** fixed-pool expiry and "PV" entries from the sheet; the app has no such concepts.

## Testing done

- **Unit:** the sheet's row (831.585 → 939.064), the chain invariant, empty months, pending movements, newest-first order, first month.
- **Scratch database, client balance-rules scenario:** Ben 1 Oct 10.000 €, return +250 €, −5.000 € (20.10.), 1 Nov 5.250 €; Carla 1 Oct 2.950 €, +91,45 €, 1 Nov 3.041,45 €; Anna +10.000 € (01.10.), +240 €. For every investor the months chain and the opening of the month after the last one equals the account balance.
- **Legacy database** (cancelled deposits, migration path): chain and balance invariant hold.
- **Browser (production build):** month change keeps search and status, search keeps month and status, paging links carry the month; view page sections, edit route and back link; the activity log shows only the investor's own 32 entries over two pages, with no admin entries, while the pool-wide log still shows all; creating an investor lands on the view page with the notice; deactivating from the list with confirmation; German and English; no horizontal page overflow at 375 / 1024 / 1280 / 1440, actions reachable at every width.
- **Follow-up testing:** select 40 px high with 14 px on both sides; popup lists all movements (Carla's August: two shown + "+1", three in the popup), closes with Esc, the close button and a backdrop click; CSV of all investors (Aug–Oct) and per investor match the table (Ben Oct: 10000,00 / 250,00 / "20.10.2026: -5000,00"); swapped months ordered; English with commas; 400 for malformed or future months, 404 for an unknown investor, login redirect without a session; loading the list three times logs no export; actions reachable at 1280 and 375.
